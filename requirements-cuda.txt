# Everything in requirements.txt, plus a CUDA build of torch. This is the pod.
#
# Check the driver before installing:
#
#     nvidia-smi
#
# The "CUDA Version" it prints in the top right is the highest the *driver*
# supports, not what is installed. A wheel from a newer channel than that fails
# at `import torch` with an insufficient-driver error.
#
# torch 2.13.0 is published for cu130 and not for cu128: the cu128 channel stops
# at 2.11.0 for cp311. So this pin needs a driver supporting CUDA 13.0.
#
# If the driver is older, or if pykeops or the S4 Cauchy extension fail to
# compile because the image ships an nvcc from a different major CUDA than the
# one this wheel bundles, the recorded fallback is
#
#     --extra-index-url https://download.pytorch.org/whl/cu128
#     torch==2.11.0+cu128
#
# applied here *and* in requirements-cpu.txt, so that the two environments stay
# on one torch version. That change is inert for every comparison in this
# repository — all 48 runs share whichever build is used, the caches depend on
# scipy rather than on torch, and the 0.941 of PROTOCOL §3 is a published
# constant rather than a local baseline — but it is not inert for the test
# suite, so `pytest -q` decides it rather than assumption. Cheapest place to
# find out is a scratch virtualenv on the laptop, where the answer is free.

-r requirements.txt

--extra-index-url https://download.pytorch.org/whl/cu130
torch==2.13.0+cu130
